# Unit generation fixtures

An isolated root for `node shell/scripts/gen-units.mjs --root <dir>`. It is laid
out like the repository so the generator never sees the production tree: four
declaration roots (`shell/common`, `shell/features`, `shell/services`,
`shell/boot`), a `qmldir` in each, and a private
`tests/shell/fixtures/unit-catalog/golden.json`. There is no seed file: all 52
rows come from `*.unit.json` declarations in one `after` chain whose first row
anchors to `__head__`.

Baseline layout:

- `shell/{common,features,services,boot}/unitNN.unit.json` — 52 declarations
  over all five providers (13 floor, 19 services, 18 features, one bar and one
  demand), each anchored to the previous id and depending only on earlier ids.
  Three declarations carry an explicit `ref` (`Common.Synthetic.tag`,
  `Services.SyntheticService.tag`, `SyntheticFeature.tag`); five carry a local
  `hooks` path next to the declaration.
- `shell/{common,features,services,boot}/unitNNHooks.qml` — authored hook
  modules covering every migrated optional-hook form: floor readiness only,
  a services observation edge (`resolve` + `ready`), a feature facade pair
  (`resolve` + `ready` + `teardown`), and the bar and annotation boot hooks
  that forward to `boot`.
- `shell/boot/Units.catalog.js` and
  `shell/boot/generated/{floor,services,features,bar,demand}/*Handlers.qml` —
  the six expected generated bytes for the coherent, all-declarations tree.
  Hook instances are expected as
  `property var <id>Hooks: Qt.createComponent("<relative path>").createObject(root, { boot: root.boot })`.
  The shipped shell engine cannot load a hook through a QML file import: both
  a plain path import and `import "..." as Alias` fail at runtime. A URL
  component load works (verified in a real shell: `Configuration Loaded`,
  `shell ready in 419ms, start 52 units, 14 essential`), and the instance is
  still inert until a generated member call reaches it. There are no static
  hook import lines in the expected output.
- `goldens/` — five complete golden variants: the baseline `golden.json`
  (held at `tests/shell/fixtures/unit-catalog/golden.json`), plus swapped-last,
  reordered, missing-row and wrong-digest variants used by the stale golden
  checks.
- `extractor/` — whole `QtObject` snippets for the narrow authored-handler
  extractor: exact `null` with a function-looking comment, two supported
  functions, a nested `ready`, a duplicate member and an unsupported value.

The fixture golden is synthetic (`unitsDigest: 7599bc3a`), never the production
one. Production compatibility is asserted in the suites: 52 declaration ids,
the pinned `aeab88b1` digest and all five providers must match the structural
golden. The production golden itself is never edited from here.
